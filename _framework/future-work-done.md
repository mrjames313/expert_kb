batch. Split out of that file on 2026-08-31: the open queue had reached ~38 items against a

- Rule 2's relative-markdown-link clause — "every relative markdown link to a repo path resolves to an existing file" — was documented from the day the rule was written and never implemented, leaving the entire non-wikilink half of the link story unenforced: `link-conventions.md` routes every reference to a file *outside* `kb/` (code, manifests, raw materials, another spec's `outcome.md`) through exactly that form. Surfaced while extending Rules 2 and 5 to spec files, and closed the next day rather than filed, because the spec work had just moved `/plan`'s spec-to-spec citations *into* the unchecked form. `extract_markdown_links` in `common.py` does the parsing: skips URL schemes, protocol-relative `//`, bare anchors and angle-bracket placeholders (`../<spec>/outcome.md`); strips a `<…>` wrap, a `"title"`, `#fragment`, `?query`, and percent-escapes; and skips fenced blocks *and* inline code spans, without which any page documenting link syntax would flag its own examples. Rule 2 resolves what's left against the containing file (leading `/` = repo-root-relative), erroring on a miss or on a path escaping the repo, with a real line number — offset past the frontmatter block, or every finding would point at the wrong line. 9 tests, including the CommonMark forms that bit during development (a bare destination cannot hold raw spaces; `<…>` and percent-escaping are the two legal ways).
